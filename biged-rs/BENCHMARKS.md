### Python Baseline Estimates

These estimates come from profiling the Python fleet (`fleet/supervisor.py`, `fleet/db.py`):

- **Startup**: ~5s includes Python interpreter boot, importing 130+ skill modules,
  SQLite connection pool init via `db.py`, and agent registration through the
  `_retry_write` DAL layer.
- **Task throughput**: ~1,500 tasks/s bottlenecked by Python GIL on SQLite writes,
  `json.dumps`/`json.loads` overhead per task, and WAL busy-retry jitter in
  `db._retry_write()`.
- **Memory**: ~50MB per agent process including Python runtime (~30MB base),
  imported modules (~15MB for 130 skills), and per-task working set (~5MB).

### Rust Advantages

- **Zero-cost abstractions**: No interpreter overhead, no GIL contention
- **Connection pooling**: r2d2 pool with 8 connections vs Python single-threaded WAL retry
- **Typed config**: `FleetConfig` parsed once at startup via serde/toml, vs Python
  dict-based `load_config()` re-reading TOML on every access
- **Event bus**: tokio broadcast channel (lock-free) vs Python threading.Event + Queue
- **Memory**: Stack-allocated structs, no per-object GC header (16 bytes saved per object)

## How to Run

```bash
# From biged-rs/
cargo bench --bench task_throughput
```

The harness uses `std::time::Instant` (no external benchmark framework).
Each benchmark is run once with the stated iteration count for simplicity.
For statistical rigor, consider wrapping with `criterion` in the future.
